## Scope

`packages/sci` now owns the Scientific Reality Core adapter boundary while
depending only on `@chemrealm/schema`. The schema package remains the single
source of truth for DTO/result shapes and their JSON Schema artifact. M3 does
not implement chemistry, PHREEQC, solver disagreement averaging, or ADR-0008's
Tier A/B/C product workflows.

## Runtime contract checks

- `SolverAdapter.solve` is `Promise<SolveResult>` for every adapter, including
  the synchronous-internally stub. The World Runtime does not call it.
- `apps/web/src/world-creation.ts` is the composition-level boundary: it
  resolves requirements before genesis and emits no event for an incompatible
  or unavailable result. Async solving begins only after a committed world
  state exists.
- `INVALID_INPUT` is returned before model-domain refusal when a typed request
  is malformed; no configured solver outcome is invoked.
- Exact registry lookup is keyed by the pair `(id, version)` and explicitly
  refuses fallback to another version.
- Requirements are checked against descriptor temperature, closed species set,
  solvent, phase, and activity-correction capability. A description string is
  not used as an applicability rule.
- Solver disagreement remains an investigation finding. No averaging or
  silent selection policy is implemented in M3.

## Known limitations carried forward

- The stub adapter is a contract fixture, not a scientific model. The v0
  `acidbase-monoprotic-davies` implementation and PHREEQC oracle validation are
  M4 scope.
- The resolver returns a selected compatible adapter/model/config for the
  composition-level genesis builder to record. Persistence availability tiers,
  re-solve, and archive behavior remain M8 scope under ADR-0008.

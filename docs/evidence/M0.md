## What changed

The repository went from three governance documents to a two-toolchain
workspace: a pnpm workspace with project references (`packages/schema`,
`apps/web`), a root `uv` project with a `.venv`, architectural import rules
enforced by dependency-cruiser, and CI that runs both toolchains.

No product behaviour exists. `apps/web` renders its own name.

## Known limitations

1. **Most architectural rules are inert.** Only `packages/schema` and
   `apps/web` exist, so `render→sci`, `ace→render`, `world→ace` and the others
   match nothing. They are proven to *fire* by the guard's fixtures, not by real
   violating code. That is the strongest evidence available before M1.
2. **`pnpm guards` proves the rules bite; it does not prove they are complete.**
   A coupling that no rule names is not caught. The rule list is derived from
   `ADR-0001` rule 2 and `ADR-0006`; a core relationship missing from those
   documents is missing here too.
3. **The coverage checker verifies mapping, not correctness.** It proves every
   `AC-*` is claimed and has an evidence row. It cannot prove the row describes
   a test that works. This packet is the layer above it.
4. **`packages/schema` is a placeholder.** One schema (`{value, unit}`) exists
   to prove zod is wired. The real contract surface — branded and opaque
   quantity types, `WorldState`, the event union, the solver result envelope,
   JSON Schema emission — is M1's, and M0 deliberately stops short of it.
5. **No jsdom, no component rendering test.** `pnpm test` asserts the module
   graph and the workspace link, not rendered output. Playwright arrives in M7.
6. **`vitest.config.ts`, not `vitest.workspace.ts`.** Deviates from
   `PLAN-0001` M0's file list, because Vitest 3.2 deprecated the workspace file.
   Recorded in the config itself.

## Two defects this milestone produced, kept for the record

Both were caught by running things rather than reading them, and both are the
same shape the project keeps meeting:

1. **CI named the pnpm version twice** — `version: 11` in the workflow and
   `packageManager: pnpm@11.22.0` in `package.json`. `pnpm/action-setup` refused
   and failed the run in 10 seconds. One version, one source of truth. This is
   `Vessel.contents` all over again, in a build file.
2. **The artifact check cried wolf on its own documentation** — its first
   version flagged every absolute URL, including the HTML comment explaining
   the rule, React's console error URLs, and a template-literal fragment from a
   bundled library. It now matches only real load positions. A check that
   produces false positives on correct code gets disabled, and then it protects
   nothing.

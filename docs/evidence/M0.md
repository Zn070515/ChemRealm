## Corrections to the first version of this packet

The owner review of `a37683a` found two claims that did not hold. Both are worth
recording because they are the failure mode this project keeps meeting.

**1. AC-V1 was claimed on an incomplete rule set.** The packet asserted the
core-boundary rules were enforced. They were not: `.dependency-cruiser.cjs`
hand-listed ten of the twelve forbidden edges and omitted `render -> ace`, which
no other rule covered. The guard sampled two representative edges, so it stayed
green. *Sampling representative cases from a matrix is not coverage of the
matrix.* The matrix is now derived from the allowed relation
(`tools/core-boundaries.cjs`), and the guard fixtures every edge.

**2. AC-P5 was claimed on a static scan, not network inspection.** The spec asks
for network inspection. A regex over build output cannot deliver it: a URL
assembled at runtime is invisible, and `sendBeacon` / `WebSocket` /
`fetch(new URL(...))` read as ordinary identifiers. The static scan is a good
*preventive guard* and is retained, but the acceptance evidence is now a real
browser capture.

## Known limitations

1. **Most architectural rules are inert.** Only `packages/schema` and
   `apps/web` exist, so the twelve core-edge rules match nothing in the real
   tree. They are proven to *fire* by fixtures, not by real violating code.
2. **The guard proves the rules bite; it does not prove they are complete.** The
   matrix is now derived, so it cannot omit an edge *between listed cores* — but
   a coupling to a package nobody added to `CORES` is caught only by the
   positive `*-imports-only-schema` rules, and a coupling through a path no rule
   names is caught by nothing.
3. **The coverage checker verifies mapping, not correctness.** It proves every
   `AC-*` is claimed and has an evidence row. It cannot prove the row describes a
   test that works. This packet is the layer above it.
4. **`packages/schema` is a placeholder.** One schema (`{value, unit}`) exists to
   prove zod is wired. The real contract surface is M1's.
5. **`tests/browser/` holds one test.** M7 owns real browser flows; this is the
   smallest thing that can honestly carry AC-P5.
6. **`vitest.config.ts`, not `vitest.workspace.ts`.** Deviates from `PLAN-0001`
   M0's file list because Vitest 3.2 deprecated the workspace file. Recorded in
   the config.

## Defects this milestone produced, kept for the record

Five, all caught by running things rather than reading them, and all the same
shape: *a silent empty or partial result read as a good outcome.*

1. **CI named the pnpm version twice** — `version: 11` in the workflow and
   `packageManager` in `package.json`. Failed the run in 10s.
2. **The artifact check flagged its own documentation**, plus React's console
   error URLs and a template-literal fragment. A check that false-positives on
   correct code gets disabled, and then protects nothing.
3. **The rule regexes matched a package importing its own source**, failing the
   clean tree on `schema/src/index.test.ts -> schema/src/index.ts`.
4. **The scratch tree was added to depcruise's `exclude`**, so the guard's
   fixtures were analysed as "0 modules" and every one reported "the rule did
   not bite" — a passing-looking result produced by analysing nothing.
5. **depcruise skips dot-prefixed directories.** The same silence, from a
   different cause. The scratch tree is no longer dot-prefixed, and both causes
   are named in comments at the site.

A sixth, from the first packet: **`render -> ace` was simply missing** from the
rule set, and the two-fixture guard could not have found it.
